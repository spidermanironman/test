## 为什么后台应用会被杀死？

### 系统保护机制

1. **资源管理**
   - 无响应的后台应用占用内存但不提供服务
   - 系统需要释放资源给其他应用使用

2. **系统稳定性**
   - 防止无响应应用影响系统整体性能
   - 避免系统卡顿或崩溃

3. **用户体验**
   - 后台应用ANR用户不可见
   - 系统自动处理，无需用户干预
   - 释放资源提升其他应用性能

### 前台 vs 后台 ANR 处理

| 特性 | 前台应用 ANR | 后台应用 ANR |
|------|------------|------------|
| 用户可见 | ✅ 显示ANR对话框 | ❌ 用户不可见 |
| 用户选择 | ✅ 等待/强制关闭 | ❌ 系统自动处理 |
| 等待时间 | 用户决定 | 系统阈值（约几分钟） |
| 最终结果 | 用户可选择 | 系统自动杀死 |

## 总结

**输入ANR → am_kill 的完整流程：**

1. ✅ **用户输入** → 应用主线程处理
2. ✅ **主线程阻塞** → 超过5秒未响应
3. ✅ **系统检测ANR** → 记录ANR事件
4. ✅ **应用进入后台** → 或继续无响应
5. ✅ **系统监控等待** → 给应用恢复机会（约9.4分钟）
6. ✅ **应用持续无响应** → 无法恢复
7. ✅ **系统决策杀死** → 释放资源
8. ✅ **执行am_kill** → 终止进程

**这是 Android 系统的正常保护机制！** 🛡️
