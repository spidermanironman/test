## 概述

Android 广播（Broadcast）是一种进程间通信机制，允许应用发送和接收系统或应用级别的消息。广播发送涉及多个系统组件和进程间的协作，主要通过 Binder IPC 机制实现。

### 核心特点
- **跨进程通信**：应用进程与系统服务进程分离
- **异步处理**：广播发送是异步的，不会阻塞调用线程
- **统一管理**：由 ActivityManagerService (AMS) 统一管理
- **权限控制**：系统服务负责权限验证

### 阶段 1: 应用层调用 (应用进程)

#### 1.1 应用代码调用

#### 1.2 ContextImpl.sendBroadcast()
**位置**: `frameworks/base/core/java/android/app/ContextImpl.java`

```java
@Override
public void sendBroadcast(Intent intent) {
    warnIfCallingFromSystemProcess();
    
    // 1. 解析 Intent 的类型
    String resolvedType = intent.resolveTypeIfNeeded(getContentResolver());
    
    try {
        // 2. 准备 Intent，标记即将离开当前进程
        intent.prepareToLeaveProcess(this);
        
        // 3. 通过 Binder 调用系统服务
        ActivityManager.getService().broadcastIntent(
            mMainThread.getApplicationThread(),  // ApplicationThread Binder 对象
            intent,                              // 要发送的 Intent
            resolvedType,                        // 解析后的类型
            null,                                // resultReceiver
            Activity.RESULT_OK,                  // resultCode
            null,                                // resultData
            null,                                // resultExtras
            AppOpsManager.OP_NONE,              // appOp
            null,                                // options
            false,                               // serialized
            false,                               // sticky
            getUserId()                          // userId
        );
    } catch (RemoteException e) {
        throw e.rethrowFromSystemServer();
    }
}
```

**关键点**:
- `intent.prepareToLeaveProcess()`: 标记 Intent 即将离开进程，进行必要的序列化准备
- `ActivityManager.getService()`: 获取 `IActivityManager` Binder 代理对象
- `mMainThread.getApplicationThread()`: 传递应用的 ApplicationThread，用于接收回调

### 阶段 3: 系统服务层处理 (系统服务进程)

#### 3.1 ActivityManagerService.broadcastIntent()
**位置**: `frameworks/base/services/core/java/com/android/server/am/ActivityManagerService.java`

```java
public final int broadcastIntent(IApplicationThread caller,
        Intent intent, String resolvedType, IIntentReceiver resultTo,
        int resultCode, String resultData, Bundle resultExtras,
        String[] requiredPermissions, int appOp, Bundle bOptions,
        boolean serialized, boolean sticky, int userId) {
    
    // 1. 权限检查
    enforceNotIsolatedCaller("broadcastIntent");
    
    // 2. 同步调用检查
    synchronized(this) {
        // 3. 验证 Intent
        intent = verifyBroadcastLocked(intent);
        
        // 4. 获取调用者信息
        final ProcessRecord callerApp = getRecordForAppLocked(caller);
        
        // 5. 权限验证
        final int callingPid = Binder.getCallingPid();
        final int callingUid = Binder.getCallingUid();
        
        // 6. 安全检查
        userId = mUserController.handleIncomingUser(callingPid, callingUid, userId);
        
        // 7. 获取或创建 BroadcastQueue
        final BroadcastQueue queue = broadcastQueueForIntent(intent);
        
        // 8. 创建 BroadcastRecord
        BroadcastRecord r = new BroadcastRecord(queue, intent, callerApp,
                callerPackage, callingPid, callingUid, resolvedType,
                requiredPermissions, appOp, brOptions, receivers, resultTo,
                resultCode, resultData, resultExtras, serialized, sticky,
                false, userId);
        
        // 9. 将广播加入队列
        boolean replaced = replacePending && queue.replaceOrderedBroadcastLocked(r);
        if (!replaced) {
            queue.enqueueOrderedBroadcastLocked(r);
            queue.scheduleBroadcastsLocked();
        }
        
        return ActivityManager.BROADCAST_SUCCESS;
    }
}
```

**关键步骤**:
1. **权限验证**: 检查调用者是否有权限发送广播
2. **Intent 验证**: 验证 Intent 的有效性
3. **用户检查**: 验证用户 ID 的有效性
4. **队列选择**: 根据 Intent 类型选择普通队列或前台队列
5. **创建记录**: 创建 BroadcastRecord 对象
6. **入队**: 将广播加入队列
7. **调度**: 触发广播处理

#### 3.2 BroadcastQueue.enqueueBroadcast()
**位置**: `frameworks/base/services/core/java/com/android/server/am/BroadcastQueue.java`

```java
public void enqueueOrderedBroadcastLocked(BroadcastRecord r) {
    // 添加到有序广播队列
    mOrderedBroadcasts.add(r);
    
    // 记录日志
    r.enqueueClockTime = SystemClock.uptimeMillis();
    
    // 如果队列为空，立即调度
    if (mOrderedBroadcasts.size() == 1) {
        scheduleBroadcastsLocked();
    }
}
```

#### 3.3 BroadcastQueue.scheduleBroadcastsLocked()
```java
final void scheduleBroadcastsLocked() {
    if (mBroadcastsScheduled) {
        return;
    }
    
    // 发送消息到 Handler，在 BroadcastQueue 线程中处理
    mHandler.sendMessage(mHandler.obtainMessage(BROADCAST_INTENT_MSG, this));
    mBroadcastsScheduled = true;
}
```

**线程模型**:
- BroadcastQueue 有专门的 HandlerThread
- 广播处理在独立的线程中进行，不阻塞主线程
- 通过 Handler 消息机制异步处理

#### 3.4 BroadcastQueue.processNextBroadcast()
```java
final void processNextBroadcast(boolean fromMsg) {
    synchronized (mService) {
        BroadcastRecord r;
        
        // 1. 处理前台队列
        while (mParallelBroadcasts.size() > 0) {
            r = mParallelBroadcasts.remove(0);
            
            // 分发到所有接收器（并行）
            for (int i = 0; i < N; i++) {
                Object target = r.receivers.get(i);
                deliverToRegisteredReceiverLocked(r, (BroadcastFilter)target, false);
            }
        }
        
        // 2. 处理有序广播
        if (mOrderedBroadcasts.size() > 0) {
            r = mOrderedBroadcasts.get(0);
            
            // 查找下一个接收器
            while (r.receivers.size() > 0) {
                Object nextReceiver = r.receivers.remove(0);
                
                // 分发到接收器（串行）
                deliverToRegisteredReceiverLocked(r, (BroadcastFilter)nextReceiver, true);
            }
        }
    }
}
```

**两种广播类型**:
1. **普通广播 (ParallelBroadcast)**: 并行发送给所有接收器
2. **有序广播 (OrderedBroadcast)**: 按优先级顺序串行发送

### 阶段 4: 分发到接收器进程

#### 4.1 deliverToRegisteredReceiverLocked()
```java
void deliverToRegisteredReceiverLocked(BroadcastRecord r,
        BroadcastFilter filter, boolean ordered) {
    
    // 1. 权限检查
    if (!checkComponentPermission(filter.requiredPermission, ...)) {
        return;
    }
    
    // 2. 获取接收器进程
    ProcessRecord app = mService.getProcessRecordLocked(
        filter.receiverList.app.processName, ...);
    
    // 3. 如果进程不存在，启动进程
    if (app == null || app.thread == null) {
        if ((r.curApp = mService.startProcessLocked(...)) == null) {
            return;
        }
    }
    
    // 4. 通过 Binder 调用接收器进程
    performReceiveLocked(filter.receiverList.app, r, filter, ordered);
}
```

---

#### 4.2 performReceiveLocked()
```java
void performReceiveLocked(ProcessRecord app, BroadcastRecord r,
        BroadcastFilter filter, boolean ordered) {
    
    if (app.thread != null) {
        try {
            // 通过 ApplicationThread Binder 调用
            app.thread.scheduleReceiver(new Intent(r.intent), filter.receiverList.receiver,
                r.resultCode, r.resultData, r.resultExtras, r.ordered, r.userId);
        } catch (RemoteException e) {
            // 处理异常
        }
    }
}
```

#### 5.2 ActivityThread.handleReceiver()
```java
private void handleReceiver(ReceiverData data) {
    // 1. 创建 ClassLoader
    LoadedApk packageInfo = getPackageInfoNoCheck(data.info.applicationInfo, ...);
    
    // 2. 创建 BroadcastReceiver 实例
    BroadcastReceiver receiver = (BroadcastReceiver)
        packageInfo.getClassLoader().loadClass(data.info.name)
        .newInstance();
    
    // 3. 创建 Context
    ContextImpl context = (ContextImpl) getApplicationContext();
    
    // 4. 调用 onReceive()
    receiver.onReceive(context.getReceiverRestrictedContext(), data.intent);
    
    // 5. 如果是有序广播，通知 AMS 处理完成
    if (data.ordered) {
        sendFinished(data);
    }
}
```

## 关键组件说明

### 1. ContextImpl
- **作用**: Context 的实现类，提供广播发送的入口
- **位置**: 应用进程
- **职责**: 准备 Intent，调用 Binder 接口

### 2. ActivityManagerService (AMS)
- **作用**: 系统服务，统一管理广播
- **位置**: 系统服务进程
- **职责**: 
  - 权限验证
  - 广播队列管理
  - 接收器查找和分发
  - 进程管理

### 3. BroadcastQueue
- **作用**: 广播队列，管理待处理的广播
- **位置**: 系统服务进程
- **类型**:
  - `mParallelBroadcasts`: 普通广播队列
  - `mOrderedBroadcasts`: 有序广播队列
- **线程**: 独立的 HandlerThread

### 4. BroadcastRecord
- **作用**: 广播记录，包含广播的所有信息
- **字段**:
  - `intent`: Intent 对象
  - `receivers`: 接收器列表
  - `callerApp`: 发送者进程
  - `resultTo`: 结果接收器

### 5. ApplicationThread
- **作用**: 应用进程的 Binder 接口
- **位置**: 应用进程
- **职责**: 接收系统服务的调用，在主线程 Handler 中调度

## Binder IPC 机制

### Binder 调用流程

```
应用进程                          Binder 驱动              系统服务进程
   │                                 │                         │
   │ 1. broadcastIntent()            │                         │
   ├─────────────────────────────────>│                         │
   │                                 │ 2. 传递数据             │
   │                                 ├─────────────────────────>│
   │                                 │                         │ 3. AMS.broadcastIntent()
   │                                 │                         │
   │                                 │ 4. 返回结果             │
   │                                 │<─────────────────────────┤
   │ 5. 返回结果                      │                         │
   │<─────────────────────────────────┤                         │
   │                                 │                         │
```

### 为什么使用 Binder？

1. **进程隔离**: 应用进程和系统服务进程分离，保证安全性
2. **高效通信**: Binder 是 Android 中最高效的 IPC 机制
3. **权限控制**: 系统服务可以验证调用者权限
4. **统一管理**: 所有广播通过 AMS 统一管理

## 广播队列处理

### 队列类型

#### 1. 普通广播队列 (ParallelBroadcasts)
- **特点**: 并行发送，所有接收器同时收到
- **使用场景**: `sendBroadcast()`
- **处理方式**: 遍历所有接收器，并行分发

#### 2. 有序广播队列 (OrderedBroadcasts)
- **特点**: 按优先级顺序串行发送
- **使用场景**: `sendOrderedBroadcast()`
- **处理方式**: 按优先级排序，逐个分发
- **优先级**: 通过 `android:priority` 设置

### 队列调度

```java
// BroadcastQueue 线程处理流程
while (true) {
    // 1. 处理普通广播
    processParallelBroadcasts();
    
    // 2. 处理有序广播
    processOrderedBroadcasts();
    
    // 3. 等待下一个广播
    waitForNextBroadcast();
}
```

## 线程模型

### 涉及的线程

1. **应用主线程**
   - 调用 `sendBroadcast()`
   - 不阻塞，立即返回

2. **BroadcastQueue 线程**
   - 系统服务进程中的独立线程
   - 处理广播队列
   - 查找和分发接收器

3. **Binder 线程池**
   - 处理 Binder IPC 调用
   - 系统自动管理

4. **接收器主线程**
   - 接收器进程的主线程
   - 执行 `onReceive()`

### 线程状态检查

正常状态:
- **RUNNABLE**: 线程正在运行
- **WAITING**: 等待消息队列（正常）

异常状态:
- **BLOCKED**: 线程被阻塞（可能死锁）
- **TERMINATED**: 线程已终止（异常）

## 性能优化要点

### 1. 避免 ANR
- `onReceive()` 中不要执行耗时操作
- 耗时操作移到后台线程或 Service

### 2. 减少广播数量
- 避免频繁发送广播
- 使用 LocalBroadcastManager（已废弃，可用替代方案）

### 3. 合理使用有序广播
- 只在需要时使用有序广播
- 普通广播性能更好

### 4. 及时注销接收器
- 动态注册的接收器要及时注销
- 避免内存泄漏

## 常见问题分析

### 问题 1: 广播发送失败

**可能原因**:
- 权限不足
- Intent 验证失败
- 系统服务异常

**排查方法**:
```bash
# 查看日志
adb logcat | grep -i broadcast

# 检查权限
adb shell dumpsys package <package_name> | grep permission
```

### 问题 2: 接收器未收到广播

**可能原因**:
- 接收器未注册
- Intent Filter 不匹配
- 进程被杀死

**排查方法**:
```bash
# 检查注册的接收器
adb shell dumpsys activity broadcasts | grep <package_name>

# 检查 Intent Filter
adb shell dumpsys package <package_name> | grep receiver
```

### 问题 3: ANR 问题

**可能原因**:
- `onReceive()` 执行时间过长
- 主线程阻塞

**解决方法**:
```java
public void onReceive(Context context, Intent intent) {
    // ❌ 错误：在主线程执行耗时操作
    // doHeavyWork();
    
    // ✅ 正确：移到后台线程
    new Thread(() -> {
        doHeavyWork();
    }).start();
    
    // ✅ 或使用 goAsync()
    final PendingResult pendingResult = goAsync();
    new Thread(() -> {
        doHeavyWork();
        pendingResult.finish();
    }).start();
}
```

### 问题 4: 线程阻塞

**检查方法**:
```bash
# 获取线程转储
adb shell dumpsys > thread_dump.txt

# 检查广播相关线程状态
grep -A 20 "BroadcastQueue" thread_dump.txt
```

## 总结

Android 广播发送全流程涉及多个进程和组件的协作：

1. **应用层**: 调用 `sendBroadcast()`，准备 Intent
2. **Binder IPC**: 通过 Binder 调用系统服务
3. **系统服务层**: AMS 验证权限，管理队列，查找接收器
4. **分发层**: 通过 Binder 调用接收器进程
5. **接收器层**: 在主线程执行 `onReceive()`

整个过程是异步的，通过 Binder IPC 实现跨进程通信，由 AMS 统一管理，保证了安全性和可靠性。
